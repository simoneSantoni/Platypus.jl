Types and Data API

For software attribution and BibTeX, see Citing Platypus.jl.

Platypus — Module
Platypus

Descriptive entity atypicality relative to a supplied collection and feature schema. Pairwise neighborhood, bounded-density, depth and copula scores expose both raw components and normalized summaries. A separate full-feature graph estimator measures connectivity. Outcome fitting is descriptive OLS, and plot functions provide backend-independent recipes.

The pairwise median/lower-tail design is inspired by Uzzi et al. (2013); IQR is an additional summary. Percentile normalization is not null calibration. See the manual and docs/research for method assumptions, validation and changes.

source

The data model separates records, collections, and projections. An EntitySet contains the analyst's selected collection and feature schema. A PairSet contains all two-feature projections and a detached source snapshot. Reference weights are graded contributions to supported estimators, not labels.

EntitySet.matrix is the authoritative mutable matrix. Entity accessors return snapshots. Rebuild pairs after editing the matrix, and refit to produce a new result. Pair coordinate vectors are shared within a PairSet; direct field mutation is an advanced operation and is not an update API.

Feature values and reference weights are stored as Float64. IDs and feature names must be unique; features must remain finite after conversion. A collection may have one feature, but build_pairs requires at least two. Constructors copy feature data; subsequent changes to the original matrix do not change the collection. Public storage is mutable even though the enclosing structs are immutable.

es[i] selects a row, not an entity ID, and returns a detached Entity. Iteration, es[:], integer-vector indexing, and Boolean-mask indexing return entity snapshots. A multirow selection returns a Vector{Entity}, not another EntitySet; use EntitySet(selected, feature_names(es)) to create a collection. ps[i] selects a FeaturePair in pair order and exposes its shared coordinates.

using Platypus

input = [1.0 4.0; 2.0 2.0; 3.0 5.0]
es = EntitySet(input, [:x, :y]; ids=[10, 20, 30])
selected = EntitySet(es[[true, false, true]], feature_names(es))
input[1, 1] = 99.0
(original=es, selected=selected)
(original = EntitySet(3 entities × 2 features), selected = EntitySet(2 entities × 2 features))

ReferenceWeights bind to input row order; they contain no entity IDs. At fitting time their length must match the collection. Pairwise estimators require at least two positive weights. Zero-weight queries are supported only by KDE, depth, and Gaussian copulas; LOF, kNN, beta copulas, and graph scoring require uniform positive weights. Supported fits recompute marginal transforms using the original represented weights. A manually constructed PairSet without source provenance cannot support nonuniform weighting.

Platypus.Entity — Type
Entity

A single entity: an id, a vector of continuous features, and an optional label.

The label is a soft, possibly fuzzy category tag (a genre, a sector, a field). It is never used to define the reference set — Platypus.jl treats the reference set as endogenous — but it is carried through so that results can be inspected by group.

Fields

  • id::Int: Identifier of the entity
  • features::Vector{Float64}: Continuous feature values, aligned to the feature schema of the enclosing EntitySet
  • label::Union{String, Nothing}: Optional category label (nothing if unlabelled)
source
Platypus.EntitySet — Type
EntitySet

A collection of Entity records sharing one feature schema.

An EntitySet is the unit of analysis and the reference set: when the boundary of the population is fuzzy or unknown, every estimator in Platypus.jl scores an entity relative to the supplied members of the same EntitySet (optionally re-weighted by ReferenceWeights).

Fields

  • entities::Vector{Entity}: Detached entity snapshots (a computed property)
  • feature_names::Vector{Symbol}: Names of the features, in column order
  • matrix::Matrix{Float64}: Authoritative n_entities × n_features value matrix
  • entity_ids::Vector{Int}: Entity IDs, in row order
  • labels::Vector{Union{String, Nothing}}: Entity labels, in row order
  • n_entities::Int: Number of entities
  • n_features::Int: Number of features

matrix is the authoritative value store. Constructors copy input data; indexing, iteration, and the entities property return detached Entity snapshots. Edit matrix explicitly to update a collection, then rebuild its pairs. Analysis functions validate direct field edits before using them.

source
Platypus.FeaturePair — Type
FeaturePair

The projection of an EntitySet onto two of its features.

Each entity contributes one point (u, v) to a two-dimensional cloud. By default the coordinates are empirical midranks in (0, 1), removing measurement units while preserving marginal order and ties. How boundaries and dependence affect typicality depends on the scoring method — see build_pairs.

Fields

  • i::Int, j::Int: Column indices of the two features (i < j)
  • name_i::Symbol, name_j::Symbol: Names of the two features
  • u::Vector{Float64}: Coordinate of feature i, one value per entity
  • v::Vector{Float64}: Coordinate of feature j, one value per entity
source
Platypus.PairSet — Type
PairSet

The set of all n(n-1)/2 FeaturePair projections of an EntitySet. This is the object fit_typicality consumes.

Fields

  • pairs::Vector{FeaturePair}: All feature pairs
  • feature_names::Vector{Symbol}: Names of the underlying features
  • entity_ids::Vector{Int}: Entity IDs, in row order
  • labels::Vector{Union{String, Nothing}}: Entity labels, in row order
  • n_entities::Int: Number of entities
  • n_pairs::Int: Number of feature pairs
  • transform::Symbol: Preprocessing used by build_pairs, or :unknown
  • source_matrix::Union{Nothing, Matrix{Float64}}: Detached raw features, allowing reference weights to be applied before preprocessing at fit time

Fitting validates that every unordered feature pair occurs exactly once; the order of the pairs is unrestricted. Known transforms require source provenance. Direct field edits are validated before analysis, but concurrent mutation while an analysis is running is unsupported.

source
Platypus.ReferenceWeights — Type
ReferenceWeights

Per-entity, non-negative weights describing graded membership in the reference set.

When the boundary of the population is fuzzy, an entity is not simply "in" or "out" of the comparison set. ReferenceWeights lets each entity contribute to the reference cloud in proportion to its weight — by recency, by a documented membership rule. They are not survey-design weights. A weight of 0 excludes an entity from reference mass while retaining it as a query where supported; uniform weights recover the plain "the collection is its own reference" case.

Nonuniform weights are supported by the :kde and :depth methods of fit_typicality and the Gaussian family of fit_copula. Other estimators reject nonuniform weights; see their documented contracts.

Fields

  • weights::Vector{Float64}: One non-negative weight per entity
source
Platypus.TYPICALITY_METHODS — Constant
TYPICALITY_METHODS

The descriptive pairwise rules accepted by fit_typicality.

  • :knn — negative kth-neighbor distance; exact search, uniform weights.
  • :lof — reciprocal tie-inclusive Local Outlier Factor; uniform weights.
  • :kde — weighted leave-one-out log density: reflected compact kernels in rank space, Gaussian kernels on real coordinates.
  • :depth — weighted global Mahalanobis centrality with an explicit singular affine-support convention. This is not a local density.

Gaussian and empirical beta copula families use fit_copula; graph connectivity uses fit_graph_typicality.

Loading and projection

Explicitly choose feature_cols when the input also contains outcomes, timestamps, or administrative variables. IDs and feature names must be unique; missing and nonfinite feature values are rejected.

load_entities accepts a CSV path or a DataFrame. Both overloads use feature_cols=nothing, id_col=:id, and label_col=nothing. With no explicit feature list, numeric columns other than ID/label columns become features; string-encoded features need explicit selection. Absent or disabled ID columns produce sequential IDs. Missing labels become nothing; missing features raise.

build_pairs(es; transform=:rank) creates all F*(F-1)/2 unordered pairs for F features, in increasing column-index order. Other transforms are :zscore and :none. The returned source_matrix is detached from es.matrix; rebuild pairs after editing the collection. Estimators require each unordered pair exactly once and reject duplicated, missing, or source-inconsistent projections. Reordering a complete, consistent pair collection is allowed.

using DataFrames

table = DataFrame(id=[10, 20, 30], x=[1, 2, 3], y=[4, 2, 5],
                  outcome=[7, 9, 8])
loaded = load_entities(table; feature_cols=[:x, :y])
pairs = build_pairs(loaded; transform=:rank)
pair_table(pairs)

load_entities(df::DataFrame; kwargs...) -> EntitySet

Build an EntitySet from a DataFrame of entity records.

Keyword Arguments

  • feature_cols::Union{AbstractVector, Nothing}=nothing: Columns holding feature values. If nothing, every numeric column other than id_col and label_col is used, in their order of appearance.
  • id_col::Union{Symbol, Nothing}=:id: Column with integer entity IDs. If the column is absent (or nothing), IDs default to 1:nrow(df).
  • label_col::Union{Symbol, Nothing}=nothing: Optional column with a category label per entity (stored as String, never used to define the reference set).

Platypus.build_pairs — Function
build_pairs(es::EntitySet; transform::Symbol=:rank) -> PairSet

Project an EntitySet onto all of its n(n-1)/2 feature pairs.

Keyword Arguments

  • transform::Symbol=:rank: per-feature transform applied before pairs are formed.
    • :rank — replace each feature by its rank rescaled to (0, 1) via (tiedrank(x) - 0.5) / n. This is the empirical copula transform: continuous untied features become marginally uniform. Tied features retain probability masses, so constant or discrete features require care. Recommended, and the default.
    • :zscore — standardise each feature to zero mean and unit variance. Keeps the marginal shape; useful when extreme marginal values should still count as atypical.
    • :none — use the raw feature values unchanged.

Pair coordinates share one vector per feature. The returned object keeps a detached raw-data snapshot and transform provenance for weighted fitting. Direct field mutation is an advanced operation; rebuild pairs after editing features. EntitySet.matrix is authoritative; entity accessors are snapshots.

Throws ArgumentError for any other transform, and for an EntitySet with fewer than two features (no pair can be formed).

Exploratory analysis

These return descriptive tables or matrices. Within-pair correlations are diagnostics, not weights for aggregating pair scores. The exploratory nearest neighbors use all features in unweighted rank space.

nearest_entities(es, idx; k=5) takes a row index and returns up to N-1 neighbors. This exploratory helper uses displayed Float64 ranks and returns at most k rows; it is not the tie-inclusive neighborhood oracle used by LOF, kNN, or graph estimators. Constant-feature correlations may be NaN, preserving their undefined status.

Platypus.rank_matrix — Function
rank_matrix(es::EntitySet) -> Matrix{Float64}

The empirical copula transform of the whole data matrix: an n_entities × n_features matrix in which every column is the focal feature replaced by its rank rescaled to (0, 1). This is the same transform build_pairs applies with transform=:rank.

source
Platypus.pair_correlations — Function
pair_correlations(es::EntitySet) -> DataFrame

Spearman (rank) correlation between every pair of features. Returns a long-form DataFrame with columns feature_a, feature_b, correlation, one row per unordered pair.

Strong correlations are the warning sign discussed in the manual: highly correlated features can create strong dependence across pair scores. Shared features and a shared fitted reference also prevent treating the pair scores as an i.i.d. sample. Within-pair correlation alone does not establish redundancy or justify downweighting that pair. See pair_redundancy.

source
Platypus.pair_redundancy — Function
pair_redundancy(ps::PairSet) -> DataFrame

Redundancy diagnostic for the feature pairs of a PairSet.

For each pair, abs_correlation is the absolute correlation between the pair's transformed coordinates. Undefined correlations (including constant features) remain NaN. Columns: feature_a, feature_b, abs_correlation. This is a descriptive diagnostic: within-pair correlation is not a justified aggregation weight and does not measure dependence between pairwise scores.

source
Platypus.nearest_entities — Function
nearest_entities(es::EntitySet, idx::Integer; k::Integer=5) -> DataFrame

The k entities closest to entity idx (a row index), measured by Euclidean distance in the copula-rank space of rank_matrix. Returns a DataFrame with columns entity_id, label, distance, sorted by increasing distance.

source
Platypus.compute_entity_statistics — Function
compute_entity_statistics(es::EntitySet) -> DataFrame

Per-entity descriptive statistics computed without fitting a model. Works on the copula-rank representation, so the statistics are comparable across features. Columns: entity_id, label, mean_rank, rank_dispersion, extremeness.

  • mean_rank — average rank of the entity across features.
  • rank_dispersion — standard deviation of those ranks.
  • extremeness — the largest deviation |rank - 0.5|, i.e. how marginally extreme the entity is on its most unusual single feature.
source

pair_table(ps::PairSet) -> DataFrame
