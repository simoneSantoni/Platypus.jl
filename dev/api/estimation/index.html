Estimation API

For software attribution and BibTeX, see Citing Platypus.jl.

This reference describes the 0.2 development API. Use Julia 1.13.2 for the default development environment. Read the Estimation guide for method selection, assumptions, reference weighting, and computational cost.

Entry pointInputResultScoring target
fit_typicalityPairSetTypicalityResultPairwise neighborhood contrast, density, or depth
fit_copulaSource-backed rank PairSetTypicalityResultGaussian or empirical beta copula density
fit_graph_typicalityEntitySetGraphTypicalityResultConnectivity across all selected features
fit_outcomeTypicalityResult, outcome vectorOutcomeResultDescriptive least-squares association

Build pair inputs with build_pairs. All scoring entry points require at least two entities; pairwise fits also require at least two features and two positive reference weights. Results retain input row order and entity IDs.

Numerical contracts

Neighbor membership uses filtered exact squared-distance comparisons with rational fallback. Both backend=:kdtree and backend=:brute currently execute the conservative scan and report effective_backend=:brute; candidate work is quadratic. Source-backed unweighted rank fits preserve doubled integer midranks; raw/z-score fits use the represented transformed binary coordinates.

Depth uses exact rational 2×2 covariance, exact algebraic rank, and strict affine support. Omit depth_rtol: numeric truncation arguments now raise. For source-backed :none and :zscore depth, the solver uses raw coordinates because invertible standardization leaves the target unchanged. Rank depth uses exact reference-weighted ranks. Per-pair metadata records effective_rank, rank_policy, support_policy, solver, and rank_truncation=false.

Density and copula computations preserve selected algebraic and reflection identities; kernels, normal quantiles, and final outputs still use floating arithmetic. No approximate-tie tolerance is applied. Exact decision predicates are not a promise of exact representation of every real-valued estimator.

Pairwise scoring

Arguments and defaults

fit_typicality(ps; kwargs...) accepts the following keywords:

KeywordDefaultAccepted values and behavior
method:lof:knn, :lof, :kde, or :depth
k0For kNN/LOF: 0 selects clamp(round(Int, sqrt(N)), 1, N-1); otherwise an integer in 1:N-1. KDE/depth require 0. Boundary ties can include more than k neighbors.
weightsnothingUniform reference by default, or a ReferenceWeights in input row order. Nonuniform weights are supported only by KDE/depth.
novelty_quantile0.1Finite real number in [0,1]; quantile across normalized pair scores
normalizetrueMust remain true; use raw-score exports to inspect unnormalized values
bandwidthnothingKDE only: automatic choice, a finite positive scalar, or (h1, h2). Rank-space bandwidths must be at most one. Values are in transformed coordinate units.
backend:kdtree:kdtree or :brute; both currently use the exact candidate scan for neighbor methods
parallelfalseSet true to score independent pairs using available Julia threads
depth_rtolnothingRetired; every non-nothing value raises. Depth uses exact algebraic rank.
provenance(;)Caller-supplied NamedTuple, copied into result metadata

Weights affect supported marginal transformations, reference fitting, and the final mid-CDF. Zero-weight rows remain queries. A positive weight that becomes zero during Float64 conversion or normalization is rejected. KDE omits the focal row's kernel contribution and renormalizes the remaining reference mass; the marginal transformation and bandwidth stay fixed at full-reference values. Depth includes the focal row when it has positive weight.

Score scales and summaries

fit_typicality returns normalized pair scores and their median, lower quantile, IQR, and complement-of-median summaries. It retains both raw_scores and the explicit normalization_scores used for ordering. fit_copula fits Gaussian or empirical beta copula densities and uses the same summary contract.

Let $r_{ep}$ be the value in normalization_scores and $w_i$ reference weights. The common normalization is

\[s_{ep} = \frac{\sum_i w_i\,\mathbf{1}(r_{ip}<r_{ep})+ \tfrac12\sum_i w_i\,\mathbf{1}(r_{ip}=r_{ep})}{\sum_i w_i}.\]

The summaries are

\[C_e=\operatorname{median}_p s_{ep},\qquad V_e=Q_q(s_{e\bullet}),\qquad D_e=\operatorname{IQR}_p s_{ep},\qquad A_e=1-C_e.\]

Here novelty is $V_e$: smaller means more unusual. Normalization is a descriptive reference percentile, not null-model calibration. Neither dispersion nor the lower quantile measures sampling uncertainty.

For Gaussian KDE on real coordinates (:none or :zscore), raw_scores contains physical log densities while normalization_scores contains Float64 ordinal labels of dimensionless leave-one-out kernel masses. The labels encode order and equality only, not density magnitude. Exact accumulation of represented exponential terms preserves distinctions that a physical-unit additive log constant can erase. Consequently, identical raw Float64 logs can have different percentiles. Other methods, including rank-space KDE, set normalization_scores equal to raw_scores.

Metadata records normalization_basis=:scale_free_kernel_order or :raw_score. Real-coordinate KDE compares direct and shifted kernel masses using a common representation $\exp(o_e)m_e$: ordinary rows have zero offset and direct rational mass; if any direct kernel underflows, the row is recomputed after shifting its unweighted kernel exponents, retaining original reference-weight ratios as exact rationals outside the exponential. A rational square of a represented half-exponential extends the range when the shifted exponential underflows. Differing offsets are compared with adaptive directed MPFR bounds on the log mass ratio, using explicit local precision and rounding. Equal offsets use rational comparisons. No global precision state is changed. These decisions certify the represented expressions, not the exact original Gaussian mixture. Even the extended shifted terms can underflow; all-negative-infinite kernel exponents yield represented mass zero, tied with other represented zeros.

Platypus.fit_typicality — Function
fit_typicality(ps::PairSet; method=:lof, k=0, novelty_quantile=0.1,
               weights=nothing, normalize=true, bandwidth=nothing,
            backend=:kdtree, parallel=false, depth_rtol=nothing,
               provenance=(;))

Fit descriptive pairwise typicality relative to the supplied collection.

  • :knn: negative kth-neighbor distance (larger is more typical), using exact search. :lof: reciprocal original, tie-inclusive Local Outlier Factor.
  • :kde: leave-one-out product log density; reflected Epanechnikov kernels on rank coordinates, Gaussian kernels on unbounded coordinates. bandwidth is a positive scalar or a pair of bandwidths; automatic bandwidth uses weighted effective sample size and the bivariate rule. No marginal-uniformity guarantee is claimed for this density estimate.
  • :depth: weighted global Mahalanobis centrality, including the focal entity; not a local-density measure. Exact rational covariance determines algebraic rank and strict affine support. Off-support depth is zero. Spectral truncation has been removed; omit the retired depth_rtol argument. Rank geometry is retained exactly, and raw/z-score depth uses original coordinate provenance.

k=0 selects rounded sqrt(N); explicit k must lie in 1:N-1. Nonuniform weights are supported by KDE/depth and applied to marginal transformations, reference fitting and score normalization. kNN/LOF reject nonuniform weights. Zero-weight rows are scored as queries but do not affect weighted references. Each pair is normalized to reference-weighted mid-percentiles before aggregation. All-equal normalization values map to 0.5. Raw method scores remain in result.raw_scores. Real-coordinate KDE normalization uses ordinal labels of the scale-free kernel ordering stored in result.normalization_scores. These labels are not density estimates. Raw Float64 log densities can therefore tie while their percentiles differ; export the ordering values with scoretable(result; normalization=true). Other methods, including rank-space KDE, use raw scores for normalization.

parallel=true independently scores pairs with Julia threads. It does not use approximate neighbors. Both requested neighbor backends currently execute a filtered exact linear scan, with quadratic work over all entities; configuration records requested and effective backends. provenance is an optional NamedTuple for dataset version, cohort selection, time cutoff and preprocessing notes; it is copied into results.

Platypus.fit_copula — Function
fit_copula(ps::PairSet; family=:gaussian, weights=nothing,
           regularization=0.0, novelty_quantile=0.1, normalize=true,
           query_clip=nothing, provenance=(;))

Score genuine fitted bivariate copula densities on transform=:rank pairs. :gaussian fits a normal-score correlation; singular fits require explicit correlation shrinkage regularization in (0,1). :beta uses the empirical beta copula of Segers, Sibuya and Tsukahara, requiring untied continuous coordinates and uniform positive weights. Beta fitting is in-sample, not leave-one-out. These model assumptions differ from LOF and nonparametric KDE. Raw scores are log copula densities; normalized summaries have the same contract as fit_typicality. This is not a null-hypothesis test.

Gaussian endpoint queries are rejected unless query_clip is supplied in (0,0.5); it clips only zero-weight endpoint queries, with the choice recorded in metadata. Positive-reference endpoints always raise an error. The beta family does not support clipping or regularization.

source
Platypus.TypicalityResult — Type
TypicalityResult

Snapshot of pairwise descriptive scores. pair_scores contains reference-weighted mid-percentiles, with larger values meaning more typical. raw_scores preserves method-specific scores, also oriented toward typicality. normalization_scores contains the values whose weighted mid-CDF defines pair_scores. These equal raw_scores except for real-coordinate KDE, which uses ordinal labels for the scale-free kernel ordering. These labels preserve ties and order; their magnitudes are not density estimates and cannot be compared across fits or pairs. Physical-unit adjustments can round distinct densities to the same Float64 raw log score; such raw ties may have different percentiles when the normalization ordering resolves the distinction. Rank-space KDE uses raw scores. Summaries always use pair_scores: median conventionality, lower-quantile novelty (smaller means more unusual), IQR dispersion, and 1 - conventionality atypicality. Neither scores nor IQR are probabilities of anomaly or sampling uncertainty.

configuration records transformation, normalized reference weights, effective sample size, algorithm settings, per-pair parameters, version, and caller-supplied provenance. Metadata and numerical arrays are detached from the inputs.

source

Copula keywords

fit_copula shares weights, novelty_quantile, normalize, and provenance with pairwise scoring. It has no k, bandwidth, backend, or parallel keyword. Pairs must come from build_pairs(es; transform=:rank).

KeywordDefaultAccepted values and behavior
family:gaussian:gaussian or :beta
regularization0.0Gaussian correlation shrinkage in [0,1); singular fits require a positive value large enough to resolve singularity. Beta requires zero.
query_clipnothingGaussian only: a finite value in (0,0.5) permits clipping zero-weight endpoint queries. Positive-reference endpoints always raise.

Gaussian fits support nonuniform reference weights but reject constant normal-score margins. Beta fits require uniform positive weights and untied margins; fitting is in-sample. These are model restrictions, not missing-value or numerical-error fallbacks.

Pairwise result fields

Write N = result.n_entities and P = result.n_pairs. Matrix rows align with entity_ids; columns align with pair_names.

FieldType or shapeMeaning
pair_scoresMatrix{Float64}, N × PWeighted mid-percentiles in [0,1]; higher means more typical
raw_scoresMatrix{Float64}, N × PNegative kth distance, reciprocal LOF, log density, or depth, depending on method
normalization_scoresMatrix{Float64}, N × POrdering values used by the mid-CDF; real-coordinate KDE uses ordinal kernel-order labels
conventionality, novelty, dispersion, atypicalityEach Vector{Float64}, length NSummaries defined above; a single pair has zero dispersion
pair_namesVector{Tuple{Symbol,Symbol}}, length POrdered feature names for each matrix column
entity_ids, labelsVectors of length NInteger IDs and optional string labels
method, k, novelty_quantile, normalizedSymbol, Int, Float64, BoolEffective fit settings; copula methods are :gaussian_copula/:beta_copula, non-neighbor k is zero, and normalized is true
configurationNamedTupleRecorded settings and provenance; use analysis_metadata for a deep copy

The three score matrices occupy 24*N*P bytes of Float64 storage, excluding summaries and metadata. They are detached from inputs but remain mutable Julia arrays. Editing them does not recompute summaries or configuration; refit to obtain a coherent new result. KDE -Inf raw scores can represent zero density.

Graph scoring

Graph scores use all features together and return a different result type. The stationary masses are proportional to weighted degree. If the graph is disconnected, this selects component mass proportional to component degree; the stationary distribution is not unique. See the result metadata for the component count and selection rule.

KeywordDefaultAccepted values and behavior
k0Automatic min(max(2, round(Int, sqrt(N))), N-1), or an integer in 1:N-1
transform:rank:rank, :zscore, or :none
weightsnothingOnly uniform positive ReferenceWeights are supported
backend:kdtree:kdtree or :brute; effective backend is currently :brute
max_edges1_000_000Positive integer limiting stored undirected edges; exceeding it raises instead of dropping ties
provenance(;)Caller-supplied NamedTuple copied into metadata

GraphTypicalityResult contains length-N vectors typicality, atypicality, stationary, and degree; a symmetric N × N sparse Float64 adjacency matrix; entity_ids, labels, n_entities, and configuration. The adjacency has no stored self-loops. Isolated vertices receive zero stationary mass when edges exist; an edgeless graph receives uniform mass. Access configuration through analysis_metadata when retaining a detached copy.

Platypus.fit_graph_typicality — Function
fit_graph_typicality(es::EntitySet; k=0, transform=:rank, weights=nothing,
                     backend=:kdtree, max_edges=1_000_000, provenance=(;))

Fit a graph on all selected features together. Exact Euclidean k-nearest neighborhoods include every boundary tie, then their union is symmetrized. An edge has affinity exp(-distance²/(σᵢ*σⱼ)), with each local scale σ equal to that vertex's kth distance (Zelnik-Manor and Perona, 2004). At zero local scale, coincident points have affinity one and noncoincident points affinity zero.

Weighted degree divided by total degree is a stationary distribution of the undirected random walk (Lovász, 1993). For disconnected graphs this explicitly selects component mass proportional to component degree; it is not unique. Isolated vertices have zero mass when any edges exist; their conceptual transition is a self-loop, but no loop is inserted in adjacency. An edgeless graph uses the uniform stationary distribution of these self-loops.

These scores describe graph connectivity, not a probability of anomaly or a pairwise score. Self-tuning affinities adapt to density, so low density does not necessarily imply low connectivity. The full-feature representation can retain interactions absent from pairwise projections, but does not guarantee their detection. Nonuniform reference weights are explicitly unsupported.

k=0 selects min(max(2, round(Int, sqrt(n))), n-1); explicit k must lie in 1:n-1. max_edges bounds stored undirected edges and throws if exact ties or large k would exceed it. Both requested search backends currently use a conservative filtered exact linear scan, because floating KD-tree pruning is not certified for exact binary geometry. Configuration records the requested and effective backends. The graph has O(nk) edges only when boundary ties are limited.

Outcome association

This is descriptive OLS. It does not create a historical reference, supply independent-observation uncertainty, or support causal interpretation. Outcome values must match the fitted result's row order.

KeywordDefaultAccepted values and behavior
predictors(:conventionality, :novelty, :dispersion)Unique selection from these three fields and :atypicality
intercepttrueInclude an intercept column
interactionfalseAdd conventionality × (1 − novelty); both main effects must be selected

The outcome vector must contain one finite real value per entity. There must be more observations than coefficients and a full-rank design. Including both conventionality and atypicality with an intercept is redundant and raises. Single-pair results have identical conventionality/novelty and zero dispersion, so the default predictor set is rank deficient for them; select fewer terms.

OutcomeResult stores coefficients and terms in design-column order, observed, fitted, residuals, entity_ids, the design matrix, scalar r2, and configuration. A constant outcome has r2=NaN. The configuration includes a detached measurement configuration under measurement. Outcome results support analysis_metadata and plot_outcome_fit, but not the score/summary table accessors.

Platypus.fit_outcome — Function
fit_outcome(r::TypicalityResult, y; predictors=(:conventionality,:novelty,:dispersion),
            intercept=true, interaction=false)

Descriptive OLS fitted with column-pivoted QR, avoiding normal equations. y must be finite, in result row order, and have one entry per entity. Supported predictors are :conventionality, :novelty, :dispersion, :atypicality. With interaction=true, adds conventionality × (1 - novelty), requiring both base terms. Rank-deficient designs are rejected rather than silently selecting one of many coefficient vectors. Including conventionality and atypicality with an intercept is therefore invalid.

This function does not construct a historical reference, establish causality, or provide uncertainty estimates. Explicitly select measurement features before fitting typicality; never include the outcome in that feature schema.

source
Platypus.OutcomeResult — Type
OutcomeResult

Descriptive least-squares fit. Stores coefficients, term names, observed/fitted outcomes, residuals, R², entity IDs, design matrix and measurement provenance. No independent-observation standard errors, p-values, causal claims, or temporal validation are implied. Dependent generated predictors need study-specific resampling that refits the measurement pipeline.

Scores, tables, and configuration

The accessors return detached vectors. Tables return detached data, and analysis_metadata returns a deep copy of the configuration. Save configuration with exported tables; tables alone cannot reconstruct the analysis. Metadata includes ordered entity_ids binding the reference_weights vector to rows. Pairwise fits also retain source_reference_weights, the original represented weights used before normalization. Preserve these mappings before sorting or joining exports.

Neighbor metadata separates requested_backend from effective_backend; backend records the effective scan. The current policy is distance_policy=:filtered_exact. The recorded geometry distinguishes exact reference midranks from source/transformed binary coordinates. Preserve the dataset, package revision, and dependency environment separately.

For a TypicalityResult, scoretable(result; raw=true) selects method-specific raw scores instead of normalized scores. scoretable(result; normalization=true) exports the values used in the mid-CDF; the two options are mutually exclusive. For real-coordinate KDE these are ordinal labels, not densities, and their magnitudes cannot be compared across pairs/fits. For a GraphTypicalityResult, raw=true selects stationary mass; normalization=true is a pairwise-result option. Graph results support atypicality, summarytable, scoretable, and analysis_metadata, but have no pairwise novelty or dispersion.

Platypus.scoretable — Function
scoretable(r::TypicalityResult; raw=false, normalization=false)

Long-form fitted pairwise scores, normalized by default. With raw=true, the typicality column contains method-specific raw_scores; their units and scale are recorded in analysis_metadata(r) and must not be compared between methods. With normalization=true, it contains normalization_scores, the values used to order and tie observations for the weighted mid-CDF. For real-coordinate KDE these are ordinal labels of the scale-free kernel ordering, not density values; they can distinguish observations whose Float64 raw log densities coincide. Their magnitudes are not comparable across pairs or fits. All other methods, including rank-space KDE, use raw scores. The two options are mutually exclusive.
